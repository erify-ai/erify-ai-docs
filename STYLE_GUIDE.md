# 👑 ERIFY™ Documentation Style Guide

Welcome to the official ERIFY™ Style Guide. Use this guide for every product, dashboard, and documentation contribution.  
Our style ensures consistency, clarity, and the Crown Values across all ERIFY™ digital assets.

---

## 🌟 Why ERIFY™ Style?

Adhering to ERIFY™ style delivers:

- A professional, luxurious, and reliable brand image
- Seamless experience for global users, builders, and partners
- Minimized confusion and friction for contributors and readers
- Easier translation and internationalization
- Alignment with ERIFY™ Crown Values

---

## 👑 Crown Values

All content must reflect ERIFY™’s four Crown Values:

- **Innovation 👑** — Lead with originality, vision, and progress.
- **Prosperity 💎** — Empower growth, wealth, and excellence.
- **Legacy 🌍** — Build for future generations and global impact.
- **Trust ⚡** — Communicate with integrity, clarity, and precision.

---

## 🏛️ Structure & Information Architecture

- **Guides/**: Tutorials, how-tos, onboarding, contributor guides
- **References/**: API docs, configuration, technical specs
- **Crown/**: Brand principles, mottos, global vision, flame archives

Follow ERIFY™ conventions for file organization and hierarchy.

---

## 📝 Content Types

Use the right content type for your material:
- **Get Started**: Quick onboarding, setup, or introduction
- **How-to**: Step-by-step task or procedure
- **Concept**: Explain principles, ideas, or product features
- **Reference**: API, config, or technical details
- **FAQ**: Common questions and answers
- **Changelog**: List of updates and release notes
- **Troubleshooting**: Problems and solutions
- **Tutorial**: Guided, multi-step walkthrough

---

## 📚 Formatting & Grammar

- Write in clear, concise, and active voice.
- Use simple, direct language (avoid jargon unless defined).
- Prefer “you” for addressing the reader.
- Use ERIFY™ product and brand names consistently.
- Capitalize Crown Values and branded terms.
- Use Oxford comma in lists.
- Prefer British English spelling unless otherwise specified.

### Code & UI

- Format code blocks with triple backticks and specify language.
- Use inline code for commands, file names, or UI elements.
- Bold important warnings or critical actions.

### Dates & Times

- Use ISO 8601 format: `YYYY-MM-DD`
- Specify time zones if relevant.

---

## ⚡ Component Guidelines

- Diagrams: Clear, labeled, ERIFY™-branded color palette.
- Screenshots: High quality, with updated UI.
- Lists: Use numbered steps for procedures, bullet points for options.
- Notes/Warnings: Use blockquotes or callouts.
- Tables: For structured data or comparisons.

---

## 🛡️ Frontmatter & Metadata

Every markdown file should include frontmatter:

```yaml
---
title: "Your Page Title"
description: "Short, clear summary."
lastUpdated: "YYYY-MM-DD"
author: "yourname"
source_url: "https://github.com/erifystudio/erify-global"
---
```

---

## 🌍 Inclusive & Global Language

- Use gender-neutral pronouns.
- Respect diverse cultures and backgrounds.
- Avoid idioms or metaphors that may not translate globally.

---

## 🏆 Contribution Standards

- PRs must use the ERIFY™ Pull Request Template.
- Follow commit message emoji standards.
- All documentation must be linted and spellchecked.
- Include screenshots for UI/appearance changes.
- Keep explanations clear for all audiences.
